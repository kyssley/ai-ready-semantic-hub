# Semantic contract 1.0 / 语义契约

The machine-readable authority is [catalog.schema.json](catalog.schema.json), generated by `semantic-hub schema`. Unknown object fields are rejected. Each catalog includes `schema_version: "1.0"`, `name`, `models`, `metrics`, `relationships` and `terms` (lists may be empty).

## Identity and physical binding

IDs and column names use lowercase `[a-z][a-z0-9_]{0,62}`. A field reference is `model_id.column_name`. Physical relations are one to three dot-separated lowercase identifiers; quoted mixed-case names and arbitrary expressions are not supported. Use a warehouse view to normalize these cases.

Each entity has `id`, `label`, `owner`, optional description, synonyms, tags and `visibility` (`public` by default or `internal`). IDs are unique within an entity kind. All model columns are visible with their parent model; there is no column ACL. Never place secrets or sensitive samples into definitions.

## Models and grain

`primary_key` is a non-empty array of declared columns. A primary key defines the intended row grain; the hub checks references and duplicates, not the warehouse's actual uniqueness. Columns have `data_type`: string, integer, number, date, timestamp or boolean; `dimension: false` disallows caller grouping/filtering on that column. Metric fixed filters may use non-dimension columns.

## Metric algebra

| Aggregation | Meaning | Required fields |
| --- | --- | --- |
| sum | SUM(column) | column |
| count | COUNT(column), or COUNT(1) when absent | optional column |
| count_distinct | COUNT(DISTINCT column) | column |
| avg | AVG(column), not a weighted average | column |
| min / max | MIN/MAX(column) | column |
| ratio | 1.0 * SUM(column) / NULLIF(SUM(denominator), 0) | column, denominator |

`sum`, `avg` and `ratio` require numeric columns. A metric belongs to one model. `filters` apply inside its aggregate, so querying two metrics with different fixed filters does not silently change either definition. SQL follows database NULL semantics: comparisons with NULL do not match; SUM over no qualifying values returns NULL, while COUNT returns zero. No implicit COALESCE is added.

`currency_dimension` requires that query requests either group by that field or constrain it with equality/single-value `IN` in query or metric filters. Multiple currencies in an `IN` filter still require grouping. No conversion rates are fetched or applied. `unit` is display metadata. `time_dimension` identifies a date/timestamp field but does not automatically bucket or constrain dates. `business_rules` are explanatory text, not executable code.

## Relationships

Each relationship has source/target model IDs and same-length column arrays. Pairing is positional. To-one targets must cover the full declared target primary key; one-to-one sources must also cover their full primary key. Types must agree.

The catalog can describe all four cardinalities. The compiler accepts only direct source-to-target `many_to_one` and `one_to_one` edges from the chosen metric model. It does not reverse edges, pick among multiple valid candidates, infer joins or traverse multiple hops. All generated joins are LEFT JOINs; filtering a target dimension may effectively remove unmatched rows, as normal SQL semantics dictate.

## Query request

```json
{
  "metrics": ["seller_gmv"],
  "dimensions": ["shops.region", "order_items.currency"],
  "filters": [{"field":"order_items.order_date","op":"gte","value":"2026-11-01"}],
  "dialect": "hologres",
  "limit": 100
}
```

Supported operators: `eq`, `ne`, `gt`, `gte`, `lt`, `lte`, `in`, `is_null`, `not_null`. `in` takes 1–100 scalar values; null operators take no value. Booleans and numbers require JSON values of the correct type; dates and timestamps require ISO-formatted strings. All query filters are ANDed; OR groups, HAVING, custom sorting and pagination are not implemented. Grouped results sort by the selected dimensions; ungrouped aggregates return one aggregate row. LIMIT bounds output rows, not warehouse scan cost.

## API inventory

| Method/path | Minimum role | Behavior |
| --- | --- | --- |
| GET `/healthz` | anonymous | Process health/version |
| GET `/api/session` | viewer | Identity, role and demo state |
| GET `/api/catalog` | viewer | Published filtered snapshot |
| GET `/api/catalog?channel=draft` | editor | Draft snapshot |
| GET `/api/schema` | viewer | JSON Schema |
| GET `/api/export` | viewer | Published YAML/JSON; drafts require editor |
| POST `/api/validate` | editor | Schema + cross-reference validation |
| POST `/api/parse-yaml` | editor | Safe YAML parsing and semantic errors |
| PUT `/api/draft` | editor | Validate/save with expected revision |
| POST `/api/publish` | admin | Promote expected draft revision |
| POST `/api/restore` | editor | Historical revision → new draft |
| GET `/api/history` | editor | Recent 100 snapshots/events, current heads |
| GET `/api/revisions/{revision}` | editor | Exact immutable snapshot |
| GET `/api/search?q=...` | viewer | Published lexical search |
| GET `/api/graph` | viewer | Visible models and relationships |
| POST `/api/context` | viewer | Published permission-filtered context |
| POST `/api/compile` | viewer | Compile only, never execute |

`401`: missing/invalid token; `403`: insufficient role; `404`: unknown revision; `409`: stale draft; `413`: request exceeds 1 MB; `422`: invalid schema, semantics or unsupported query. Inspect `/openapi.json` for exact request shapes.
